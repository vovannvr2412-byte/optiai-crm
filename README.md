# OptiAI CRM

Revenue Operating System для продаж SEO + GEO на автопилоте.

Проект собран по ТЗ:

- Backend: PostgreSQL, Supabase, API-first.
- Frontend: Next.js, React, Tailwind.
- CRM-механики: воронка, карточка компании, аккаунты, роли, задачи, звонки, AI-summary, прогревы, подписки, платежи, продления, интеграции.

## Запуск

```bash
npm install
npm run dev
```

Открыть: `http://localhost:3000`.

Без Supabase-ключей интерфейс и основная бизнес-логика работают в локальном режиме. Аккаунты сотрудников, восстановление пароля и постоянная работа с нескольких устройств требуют Supabase.

## Вход в CRM

В локальном demo-mode включен вход по email и паролю через HTTP-only cookie-сессию. Список аккаунтов и паролей не показывается на странице входа.

Новые аккаунты создаёт руководитель или РОП во вкладке `Команда`: указывает email и временный пароль. Пароль передаётся только в Supabase Auth и не сохраняется в таблицах CRM или журнале аудита. После входа сотрудник меняет его через кнопку `Сменить пароль`.

Для production нужно задать `AUTH_SECRET` в `.env.local`. При HTTPS также выставить `AUTH_COOKIE_SECURE=true`.

В production используется Supabase Auth. Поддерживаются создание аккаунтов руководителем, восстановление и смена пароля, отзыв сессий, блокировка и удаление аккаунта. Подробно: `supabase/AUTH_SETUP.md`.

## Supabase

1. Создать Supabase project.
2. Скопировать `.env.example` в `.env.local`.
3. Заполнить:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

4. Выполнить SQL:

```text
supabase/migrations/0001_initial_schema.sql
supabase/seed.sql
supabase/migrations/0002_messaging_center.sql
supabase/migrations/0003_media_storage.sql
supabase/migrations/0004_normalized_crm_and_auth.sql
supabase/migrations/0005_single_company_security.sql
supabase/migrations/0006_tasks_and_automations.sql
supabase/migrations/0007_telegram_bot_replacement.sql
supabase/migrations/0008_external_integrations_and_web_push.sql
supabase/migrations/0009_warmup_editor_and_ai.sql
supabase/migrations/0010_ai_messaging_autopilot.sql
```

`0004_normalized_crm_and_auth.sql` переключает CRM с общей JSON-записи на нормализованные таблицы. При первом входе приложение сохраняет резервную копию `crm_state_backup_v1`, переносит связанные сущности, обновляет идентификаторы диалогов и создаёт маркер `normalized_storage_v1`.

`0005_single_company_security.sql` добавляет жизненный цикл аккаунтов, журнал безопасности и точные RLS-права для одной компании. Менеджер получает только назначенные ему сделки, аккаунт-менеджер - только назначенных действующих клиентов. Секреты интеграций шифруются сервером через AES-256-GCM и не возвращаются в браузер.

`0006_tasks_and_automations.sql` добавляет постоянные уведомления, журнал запусков, идемпотентные события автоматизаций и жизненный цикл задач. Настройка ежедневного запуска описана в `supabase/AUTOMATIONS_SETUP.md`.

`0008_external_integrations_and_web_push.sql` добавляет Instagram и Avito в центр сообщений, журнал реального обмена с Google Sheets и Яндекс Метрикой, защиту конверсий от повторной отправки и Web Push-подписки устройств. Пошаговая настройка находится в `INTEGRATIONS_SETUP.md`.

`0009_warmup_editor_and_ai.sql` регистрирует серверную AI-интеграцию. Редактор прогревов поддерживает несколько цепочек, переименование, включение, удаление, редактирование шагов, вложения и ручное назначение конкретному лиду.

`0010_ai_messaging_autopilot.sql` добавляет режим AI для каждого диалога. Он нужен для автоматических ответов, ручной передачи менеджеру и независимой паузы автопилота в отдельных чатах.

Схема содержит:

- `crm_users` - аккаунты руководителя, РОПа, менеджеров, аккаунт-менеджеров;
- `companies`, `contacts`, `leads` - карточка компании и лид;
- `pipeline_stages` - 13 этапов из ТЗ;
- `tasks` - задачи менеджеров и автоматизаций;
- `activities` - история коммуникаций;
- `call_records` - запись, расшифровка, summary, возражения, вероятность сделки;
- `warmup_sequences`, `warmup_steps`, `warmup_assignments` - система прогрева;
- `subscriptions`, `payments` - подписки, платежи, продления;
- `integrations` - Telegram, WhatsApp, MAX, Instagram, Avito, Google Sheets, Яндекс Метрика, RoboKassa, SIP.
- `security_audit_log` - входы и административные действия без паролей и API-ключей.

RLS-политики ограничивают доступ:

- Руководитель: полный доступ;
- РОП: управление продажами и командой;
- Менеджер: свои сделки;
- Аккаунт-менеджер: действующие клиенты.

## API-first слой

Клиент работает через API:

- `GET /api/crm/bootstrap` - состояние CRM, отфильтрованное по защищённой сессии;
- `GET/PATCH /api/notifications` - уведомления текущего сотрудника и отметка о прочтении;
- `GET /api/cron/automations` - защищённый ежедневный запуск автоматизаций;
- `POST /api/crm/actions` - бизнес-действия:
  - `create_user`;
  - `create_lead`;
  - `record_call_result`;
  - `move_stage`;
  - `assign_lead`;
  - `record_call`;
  - `send_message`;
  - `start_warmup`;
  - `create_warmup_step`;
  - `mark_paid`;
  - `mark_refused`;
  - `renew_subscription`;
  - `run_automation`;
  - `complete_task`;
  - `reschedule_task`;
  - `cancel_task`;
  - `toggle_integration`.

## Задачи и автоматизации

- задачи можно выполнить, перенести или отменить;
- пропущенный звонок создаёт задачи на 1, 3 и 7 дней;
- наступившие задачи сохраняются в центре уведомлений;
- цепочки прогрева выполняются по дням автоматически и без повторной отправки одного шага;
- при отсутствии ответа CRM отправляет сообщение через 3 дня, ставит задачу через 7 дней и запускает повторный прогрев через 14 дней;
- по активным подпискам создаются напоминания за 30, 14, 7 и 3 дня до окончания;
- Vercel Cron запускает обработку ежедневно в 06:00 UTC (09:00 по Москве).
- тот же Cron выполняет настроенный двусторонний обмен Google Sheets и выгрузку новых оплат в Яндекс Метрику;
- фоновые Web Push-уведомления приходят даже при закрытой вкладке после разового разрешения на каждом устройстве.

## AI-ассистент

Руководитель подключает OpenAI, Claude или Gemini в разделе `Автоматизации -> AI-ассистент`. Провайдер, модель, правила общения и API-ключ сохраняются в зашифрованном серверном хранилище; ключ не возвращается в браузер и не попадает в Git.

AI-автопилот отвечает на новые входящие сообщения Telegram, WhatsApp и MAX через уже подключённые каналы. Руководитель отдельно выбирает каналы, включает автоматические ответы и AI-персонализацию прогревов. Жалобы, договоры, платежи, индивидуальные условия, вложения и прямой запрос человека переводят диалог на менеджера с CRM- и Push-уведомлением. Ручной ответ менеджера ставит AI на паузу только в этом диалоге; вернуть автопилот можно в центре сообщений.

Плановый прогрев продолжает выполняться Vercel Cron. При включённой персонализации AI адаптирует утверждённый текст шага под карточку лида и историю диалога, а при недоступности AI CRM отправляет исходный шаблон, чтобы цепочка не остановилась.

До подключения телефонии реальную расшифровку можно вставить вручную в `Call Center`. Endpoint `POST /api/ai/analyze-call` уже готов и после подключения SIP сможет принимать расшифровки автоматически. Результат проходит строгую проверку структуры и сохраняет summary, боль, каналы продвижения, бюджет, возражения, следующие шаги, контент для прогрева, интерес, вероятность сделки и ошибки менеджера.

## Метрики

Дашборд рассчитывает показатели только из фактических данных CRM: лиды, звонки, уникальные оплаченные сделки, число оплат, выручку, MRR активных месячных подписок, churn отменённых подписок, фактический LTV, средний срок клиента, сквозную конверсию, переходы между этапами, каналы и показатели менеджеров. Демонстрационные коэффициенты и вымышленные значения не используются.

## Внешний обмен

- Instagram и Avito принимают webhook-события и отправляют реальные ответы из центра сообщений;
- Avito умеет загрузить существующую историю чатов по команде руководителя;
- Google Sheets синхронизирует лиды в обе стороны по `CRM_ID` или телефону;
- Яндекс Метрика получает только новые оплаченные конверсии, а CRM хранит ключ каждой выгрузки против дублей;
- ключи меняются руководителем в интерфейсе, шифруются через `AUTH_SECRET` и не возвращаются в браузер.

## Работа без телефонии

На этапах `Первый звонок` и `Не дозвонились` кнопка `Позвонить` открывает системный обработчик телефона через `tel:`. После возвращения в CRM менеджер вручную фиксирует один результат:

- `Дозвонился` - переводит лида к состоявшемуся разговору и ставит задачу отправить аудит;
- `Не дозвонился` - переводит лида на соответствующий этап и ставит перезвоны через 1, 3 и 7 дней;
- `Назначена встреча` - увеличивает показатель встреч и ставит задачу на подготовку;
- `Только комментарий` - сохраняет заметку без изменения этапа и показателей.

Пока телефония не подключена, CRM не создаёт вымышленные записи, расшифровки и AI-summary. Эти данные появятся только после подключения реального SIP или сервиса записи звонков.

## Рабочий сценарий менеджера

1. Открыть CRM утром.
2. Выбрать свой аккаунт.
3. Перейти в `Воронка` или `Call Center`.
4. Сделать звонки из списка.
5. После подключения AI-провайдера анализ звонка заполняет карточку, summary, боль, возражения и следующий шаг.
6. CRM запускает прогрев или ставит задачу.
7. Руководитель видит прогноз, MRR, Churn, LTV, конверсии и статус каждого клиента.
