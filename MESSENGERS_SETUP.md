# Подключение мессенджеров OptiAI CRM

Модуль хранит диалоги и сообщения локально в `data/messaging-state.json`, когда включён `CRM_FORCE_LOCAL=true`. В production с настроенным Supabase используются таблицы из миграции `supabase/migrations/0002_messaging_center.sql`, а фото и видео — bucket из `supabase/migrations/0003_media_storage.sql`.

## Общая настройка

1. Выполните миграции `0002_messaging_center.sql`, `0003_media_storage.sql`, `0007_telegram_bot_replacement.sql`, `0008_external_integrations_and_web_push.sql` и `0010_ai_messaging_autopilot.sql` в Supabase SQL Editor по порядку.
2. Войдите как руководитель и откройте «Автоматизации» → нужный мессенджер → «Настроить».
3. Введите ключи в форму и нажмите «Сохранить ключи», затем «Проверить подключение».
4. Зарегистрируйте показанный в форме Webhook URL в кабинете провайдера.
5. Webhook должен быть доступен по публичному HTTPS-адресу.

Ключи, введённые в CRM, шифруются алгоритмом AES-256-GCM с ключом на основе `AUTH_SECRET`. В production зашифрованный контейнер хранится в `crm_app_state`, поэтому настройки переживают Redeploy Vercel. Значения никогда не возвращаются в браузер: интерфейс показывает только признак наличия.

Переменные из `.env.local` и Vercel остаются резервным способом настройки. Не используйте префикс `NEXT_PUBLIC_` для токенов и webhook-секретов. После изменения переменных нужен перезапуск или Redeploy. Не меняйте `AUTH_SECRET` после сохранения ключей в CRM, иначе их нельзя будет расшифровать.

## Telegram

1. Создайте бота через `@BotFather` и вставьте токен в поле Bot Token.
2. Создайте случайный секрет из символов `A-Z`, `a-z`, `0-9`, `_`, `-` и вставьте его в поле Webhook Secret.
3. При сохранении ключей на production CRM автоматически установит webhook на `https://ВАШ-ДОМЕН/api/messaging/webhooks/telegram` с тем же `secret_token`.
4. В CRM откройте «Автоматизации» → «Мессенджеры» → Telegram → «Проверить».
5. Напишите боту. Диалог появится в разделе «Мессенджеры».

Бот видит только события в чатах, к которым ему предоставлен доступ. Он не читает произвольные личные переписки сотрудников.

### Заявка на звонок из Telegram

CRM создаёт или находит лида только после явной заявки в личном чате. Поддерживаются команды `/call`, `/callback`, `/manager`, `/request_call`, точные фразы «Позвонить мне», «Связаться с менеджером», «Запросить звонок», «Запросить звонок менеджера», а также inline-кнопка с `callback_data: manager_call_requested`. Обычные сообщения и `/start` остаются перепиской и сами по себе лидов не создают.

Заявка объединяется с существующей карточкой по Telegram ID, сохраняется как событие источника и автоматически привязывает диалог к ответственному менеджеру. После обновления проекта повторно сохраните Telegram-подключение или нажмите «Заменить бота», чтобы webhook начал принимать `callback_query` от inline-кнопок.

### Замена Telegram-бота

1. В «Автоматизации» откройте настройки Telegram и вставьте токен нового бота. Сохранённый Webhook Secret можно оставить без изменений.
2. Нажмите «Заменить бота». CRM сначала проверит токен через `getMe`, сохранит старые фото и видео в bucket `crm-media`, затем зарегистрирует webhook и только после этого сохранит подключение.
3. Все диалоги, текстовая история, сохранённые медиа, связи с лидами и ответственные остаются на месте. Диалоги будут помечены как ожидающие `/start`.
4. Отправьте клиентам ссылку на нового бота. После первого `/start` или другого входящего сообщения CRM автоматически активирует отправку в соответствующем диалоге.
5. Webhook предыдущего бота отключается без удаления ожидающих обновлений.

Telegram не позволяет новому боту первым начать личный диалог. Поэтому CRM не имитирует перенос доступа: история переносится сразу, а возможность отправки включается отдельно для каждого клиента после его сообщения новому боту.

Новые входящие фото и видео сразу копируются в хранилище CRM, поэтому они не зависят от дальнейшей смены токена. Если старый бот уже отозван или Telegram не отдаёт отдельный файл, CRM сохранит само сообщение и явно покажет число файлов, которые не удалось перенести. События и сообщения хранятся с ID бота, поэтому совпадающие номера сообщений разных ботов не создают ложных дублей.

## WhatsApp Business Cloud API

1. В Meta for Developers создайте приложение Business, добавьте WhatsApp и подключите номер.
2. В форме CRM заполните Access Token, Phone Number ID и App Secret.
3. Придумайте проверочный токен и укажите его в поле Verify Token.
4. В настройках webhook укажите `https://ВАШ-ДОМЕН/api/messaging/webhooks/whatsapp`, проверочный токен и подпишитесь на поле `messages`.
5. Проверьте подключение из CRM и отправьте входящее сообщение на бизнес-номер.

Исходящие сообщения подчиняются 24-часовому окну обслуживания и правилам шаблонов WhatsApp. CRM не обходит эти ограничения; ошибки Cloud API сохраняются у сообщения.

Для автоматического прогрева создайте и дождитесь одобрения Meta-шаблонов:

- текстовый шаблон с одним параметром в теле для текста шага;
- отдельный шаблон с `image` header и одним параметром в теле, если прогрев содержит фото;
- отдельный шаблон с `video` header и одним параметром в теле, если прогрев содержит видео.

Имена шаблонов и код языка указываются в настройках WhatsApp внутри CRM. Обычные AI-ответы после нового входящего сообщения отправляются как свободный текст внутри открытого окна обслуживания.

## AI-автопилот

1. Выполните миграцию `0010_ai_messaging_autopilot.sql`.
2. Подключите Telegram, WhatsApp и/или MAX и убедитесь, что входящие сообщения появляются в CRM.
3. Откройте «Автоматизации» → «AI-ассистент», задайте провайдера, модель, API-ключ, проверенные сведения об услугах и правила общения.
4. Выберите каналы, включите автоматические ответы и при необходимости персонализацию прогревов.
5. В центре сообщений AI можно поставить на паузу отдельно для каждого диалога. Ручной ответ менеджера также автоматически ставит этот диалог на паузу.

AI не отвечает на вложения и переводит на менеджера жалобы, договорные и платёжные вопросы, индивидуальные цены и прямые просьбы соединить с человеком. Передача создаёт уведомление ответственному, а для неназначенного диалога — руководителю.

## MAX

1. Создайте бота на платформе MAX для партнёров и вставьте токен в поле Bot Token.
2. Создайте секрет длиной 5–256 символов из разрешённых символов и вставьте его в поле Webhook Secret.
3. Вызовите `POST https://platform-api2.max.ru/subscriptions` с заголовком `Authorization: <токен>` и телом:

```json
{
  "url": "https://ВАШ-ДОМЕН/api/messaging/webhooks/max",
  "update_types": ["message_created", "bot_started"],
  "secret": "ВАШ_MAX_WEBHOOK_SECRET"
}
```

4. Проверьте подключение из CRM и напишите боту.

Для production MAX требует HTTPS webhook на порту 443 и доверенный TLS-сертификат. Актуальный API использует домен `platform-api2.max.ru`.

## Instagram

1. Используйте профессиональный Instagram-аккаунт и приложение Meta с Instagram Login.
2. Получите долгоживущий Access Token с правами `instagram_business_basic` и `instagram_business_manage_messages`, а также Instagram Account ID.
3. В Meta Webhooks задайте callback `https://ВАШ-ДОМЕН/api/messaging/webhooks/instagram`, тот же Verify Token из CRM и подпишитесь на события сообщений.
4. В CRM заполните Access Token, Account ID, Verify Token и App Secret. При сохранении CRM проверит аккаунт и подпишет приложение на события аккаунта.
5. Клиент должен первым написать профессиональному аккаунту. После webhook диалог появится в центре сообщений.

## Avito

1. Создайте приложение в кабинете Avito API и получите Client ID и Client Secret с доступом к Messenger API.
2. Придумайте Webhook Secret и заполните форму Avito в CRM. User ID можно не указывать: CRM запросит его у `/core/v1/accounts/self`.
3. На production CRM зарегистрирует защищённый webhook автоматически. Секрет добавляется в callback URL и проверяется при каждом входящем запросе.
4. Нажмите «Загрузить историю», чтобы получить текущие чаты и сообщения. Повторный импорт не создаёт дубли.
5. Из CRM можно отправлять текст и изображения. Видео не поддерживается Messenger API Avito и явно отклоняется интерфейсом провайдера.

## Проверка

- В настройках канал должен перейти из «Не настроен» в «Подключён» только после успешного ответа API.
- Входящее сообщение должно создать один диалог и одно сообщение. Повторная доставка того же события не создаёт копию.
- Исходящее сообщение сначала сохраняется со статусом `pending`, затем получает `sent` либо `failed` с безопасным описанием ошибки.
- Фото до 5 МБ и видео до 16 МБ должны загружаться в `crm-media`, отправляться в канал и отображаться в истории диалога.
- Менеджер по продажам видит только диалоги лидов, назначенных на его аккаунт. Руководитель видит все диалоги, включая ещё не связанные с лидом.
- Для проверки на локальном компьютере нужен HTTPS-туннель. `localhost` провайдеры вызвать не смогут.
