# Подключение мессенджеров OptiAI CRM

Модуль хранит диалоги и сообщения локально в `data/messaging-state.json`, когда включён `CRM_FORCE_LOCAL=true`. В production с настроенным Supabase используются таблицы из миграции `supabase/migrations/0002_messaging_center.sql`, а фото и видео — bucket из `supabase/migrations/0003_media_storage.sql`.

## Общая настройка

1. Выполните миграции `0002_messaging_center.sql` и `0003_media_storage.sql` в Supabase SQL Editor по порядку.
2. Войдите как руководитель и откройте «Автоматизации» → нужный мессенджер → «Настроить».
3. Введите ключи в форму и нажмите «Сохранить ключи», затем «Проверить подключение».
4. Зарегистрируйте показанный в форме Webhook URL в кабинете провайдера.
5. Webhook должен быть доступен по публичному HTTPS-адресу.

Ключи, введённые в CRM, шифруются алгоритмом AES-256-GCM с ключом на основе `AUTH_SECRET`. В production зашифрованный контейнер хранится в `crm_app_state`, поэтому настройки переживают Redeploy Vercel. Значения никогда не возвращаются в браузер: интерфейс показывает только признак наличия.

Переменные из `.env.local` и Vercel остаются резервным способом настройки. Не используйте префикс `NEXT_PUBLIC_` для токенов и webhook-секретов. После изменения переменных нужен перезапуск или Redeploy. Не меняйте `AUTH_SECRET` после сохранения ключей в CRM, иначе их нельзя будет расшифровать.

## Telegram

1. Создайте бота через `@BotFather` и вставьте токен в поле Bot Token.
2. Создайте случайный секрет из символов `A-Z`, `a-z`, `0-9`, `_`, `-` и вставьте его в поле Webhook Secret.
3. Установите webhook методом `setWebhook` на `https://ВАШ-ДОМЕН/api/messaging/webhooks/telegram`, передав тот же `secret_token`.
4. В CRM откройте «Автоматизации» → «Мессенджеры» → Telegram → «Проверить».
5. Напишите боту. Диалог появится в разделе «Мессенджеры».

Бот видит только события в чатах, к которым ему предоставлен доступ. Он не читает произвольные личные переписки сотрудников.

## WhatsApp Business Cloud API

1. В Meta for Developers создайте приложение Business, добавьте WhatsApp и подключите номер.
2. В форме CRM заполните Access Token, Phone Number ID и App Secret.
3. Придумайте проверочный токен и укажите его в поле Verify Token.
4. В настройках webhook укажите `https://ВАШ-ДОМЕН/api/messaging/webhooks/whatsapp`, проверочный токен и подпишитесь на поле `messages`.
5. Проверьте подключение из CRM и отправьте входящее сообщение на бизнес-номер.

Исходящие сообщения подчиняются 24-часовому окну обслуживания и правилам шаблонов WhatsApp. CRM не обходит эти ограничения; ошибки Cloud API сохраняются у сообщения.

## MAX

1. Создайте бота на платформе MAX для партнёров и вставьте токен в поле Bot Token.
2. Создайте секрет длиной 5–256 символов из разрешённых символов и вставьте его в поле Webhook Secret.
3. Вызовите `POST https://platform-api2.max.ru/subscriptions` с заголовком `Authorization: <токен>` и телом:

```json
{
  "url": "https://ВАШ-ДОМЕН/api/messaging/webhooks/max",
  "update_types": ["message_created", "bot_started"],
  "secret": "ВАШ_MAX_WEBHOOK_SECRET"
}
```

4. Проверьте подключение из CRM и напишите боту.

Для production MAX требует HTTPS webhook на порту 443 и доверенный TLS-сертификат. Актуальный API использует домен `platform-api2.max.ru`.

## Проверка

- В настройках канал должен перейти из «Не настроен» в «Подключён» только после успешного ответа API.
- Входящее сообщение должно создать один диалог и одно сообщение. Повторная доставка того же события не создаёт копию.
- Исходящее сообщение сначала сохраняется со статусом `pending`, затем получает `sent` либо `failed` с безопасным описанием ошибки.
- Фото до 5 МБ и видео до 16 МБ должны загружаться в `crm-media`, отправляться в канал и отображаться в истории диалога.
- Менеджер должен видеть только диалоги лидов, назначенных на его аккаунт. Руководитель и РОП видят все диалоги, включая ещё не связанные с лидом.
- Для проверки на локальном компьютере нужен HTTPS-туннель. `localhost` провайдеры вызвать не смогут.
