# Реальные интеграции и Web Push OptiAI CRM

## Обязательная миграция

После миграций `0001`-`0007` выполните целиком в Supabase SQL Editor:

```text
supabase/migrations/0008_external_integrations_and_web_push.sql
```

После миграции сделайте Redeploy Vercel. Все ключи ниже можно вводить руководителю прямо в CRM: `Автоматизации` -> нужная интеграция -> `Настроить`. Переменные Vercel из `.env.example` остаются резервным вариантом.

## Google Sheets

1. В Google Cloud создайте проект, включите Google Sheets API и создайте Service Account.
2. Скачайте JSON-ключ сервисного аккаунта.
3. Создайте отдельный лист с названием `CRM` и выдайте email сервисного аккаунта право редактора на таблицу.
4. Возьмите Spreadsheet ID из URL между `/d/` и `/edit`.
5. В CRM вставьте Spreadsheet ID, диапазон `CRM!A:V` и полное содержимое JSON-файла.
6. Нажмите `Сохранить и проверить`, затем `Синхронизировать`.

CRM читает первые 500 строк, ищет лид по `CRM_ID` или телефону, импортирует изменения и записывает обратно канонические данные. Не используйте этот лист для несвязанных таблиц: во время синхронизации диапазон очищается и заполняется заново.

## Яндекс Метрика

1. Создайте OAuth-приложение Яндекса с правами чтения и записи Метрики и получите OAuth Token владельца счётчика.
2. Возьмите Counter ID и создайте JavaScript-событие для подтверждённой оплаты; его идентификатор укажите как Goal ID.
3. Выберите источник UserId. На сайте должен отправляться тот же идентификатор: `lead_id`, email или телефон.
4. Нажмите `Сохранить и проверить`, затем `Синхронизировать`.

CRM выгружает CSV offline conversions только для платежей со статусом `paid`. Таблица `integration_export_events` не допускает повторной отправки одного платежа. Также CRM получает реальные визиты и пользователей за 30 дней; результат каждого обмена сохраняется в `integration_sync_runs`.

## Instagram и Avito

Инструкции по ключам, webhook и проверке входящих/исходящих сообщений находятся в `MESSENGERS_SETUP.md`. Ключи можно заменить без изменения кода и Vercel Environment Variables. Существующие диалоги остаются в CRM; новый провайдерский аккаунт сможет продолжить только те разговоры, к которым сам провайдер даёт доступ.

## Автоматический обмен

`vercel.json` вызывает `/api/cron/automations` ежедневно в 06:00 UTC. После обычных задач CRM планировщик автоматически:

- синхронизирует Google Sheets, если ключи настроены;
- отправляет новые оплаты в Яндекс Метрику;
- пропускает ненастроенные интеграции;
- возвращает по каждой интеграции `completed`, `failed` или `skipped`.

Для Cron в Vercel обязательно задайте `CRON_SECRET`. Один и тот же запуск не дублирует оплаты и автоматические события.

## Web Push

1. Выполните миграцию `0008` и откройте CRM по HTTPS.
2. Руководитель первым нажимает колокольчик -> `Включить фоновые push-уведомления`. CRM автоматически создаёт VAPID-ключи и хранит их в зашифрованном виде.
3. Каждый сотрудник повторяет включение на своих устройствах.
4. Уведомления о задачах, перезвонах, прогревах, продлениях и новых сообщениях приходят через Service Worker даже при закрытой вкладке.
5. Кнопка `Отключить push на этом устройстве` удаляет только текущую подписку.

На iPhone Web Push работает для установленного на экран «Домой» веб-приложения и после явного разрешения пользователя. HTTP и localhost не подходят для production push; используйте домен Vercel с HTTPS.
