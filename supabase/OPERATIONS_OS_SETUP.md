# Развёртывание OptiAI Operations OS

## 1. Миграция

После миграций `0001`-`0010` выполните целиком:

```text
supabase/migrations/0011_operations_os.sql
```

Файл можно выполнить повторно. Он обновляет справочник этапов, переносит старые сделки в новую модель и создаёт таблицы Operations OS. После применения не запускайте старый `seed.sql` повторно: он предназначен только для первоначального создания системных данных.

## 2. Планировщик

Endpoint `GET /api/cron/automations` выполняет существующие автоматизации и обработку отложенных регистраций OptiAI. Для Vercel задайте `CRON_SECRET`; значение не должно иметь префикс `NEXT_PUBLIC_`.

Отложенная регистрация становится лидом на следующий календарный день. Если для того же аккаунта уже пришёл запрос настройки или успешная оплата, дублирующий регистрационный лид не создаётся.

## 3. События OptiAI

В настройках интеграции задайте `Webhook secret`. Источник отправляет JSON на:

```text
POST https://<домен>/api/webhooks/optiai
```

Тело подписывается HMAC-SHA256; hex-подпись передаётся в `x-optiai-signature`. Поддерживаемые события:

```text
setup_requested
manager_call_requested
account_registered
payment_succeeded
account_connected
subscription_expired
subscription_renewed
document_synced
```

Для `document_synced` передаются `account_id`, `document_external_id`, `document_kind` (`invoice`, `act`, `contract`, `other`), `title`, `status`, а при наличии — `file_url` и `amount`. Повтор с тем же внешним ID обновляет документ, а не создаёт копию.

У каждого события обязателен уникальный `eventId`. Повтор не меняет CRM второй раз.

## 4. SIP

Провайдер телефонии отправляет результат на:

```text
POST https://<домен>/api/webhooks/sip
```

JSON подписывается секретом SIP в заголовке `x-sip-signature`. Нужны внешний идентификатор звонка, телефон, результат, время начала и, если доступны, длительность и URL записи. CRM связывает звонок с лидом по нормализованному номеру и игнорирует повторный внешний идентификатор.

## 5. Проверка после деплоя

1. Войти руководителем и убедиться, что на главном экране видны шесть приложений.
2. В `Команда` назначить сотруднику приложения и проверить прямой URL под его аккаунтом.
3. Создать тестового лида без вымышленных платежей и пройти этапы до подключения.
4. Убедиться, что подключённый клиент исчез из активной воронки и появился в `Панель управления`.
5. Проверить повторную отправку одного `eventId`: состояние не должно измениться второй раз.
6. Открыть `Рутины` в двух сессиях и проверить, что конфликт версий не перезаписывает чужое изменение.

Секреты хранятся только на сервере: в Vercel Environment Variables или в зашифрованной конфигурации интеграции. Не добавляйте рабочие ключи в Git.
